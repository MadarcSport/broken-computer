# Shader Sphere Learning Notes

This file explains the blinking glow shader behavior currently used on your inner sphere in `src/components/Scene3D_2.tsx`.

## 1. What You Are Doing Right Now

Your sphere still uses `meshStandardMaterial`, but you modify the generated GLSL shader code with `onBeforeCompile`.

This is a great beginner path because:

- You keep physically based lighting from `meshStandardMaterial`.
- You inject only a small custom GLSL block.
- You can animate uniforms from React (`useFrame`).

## 2. How the Shader Is Attached to the Sphere

Inside your sphere material:

```tsx
<meshStandardMaterial
  color="#ff8a00"
  emissive="#ff7a00"
  onBeforeCompile={(shader) => {
    shader.uniforms.uTime = { value: 0 };
    shader.uniforms.uPulseSpeed = { value: 0.3 };
    shader.uniforms.uPulseMin = { value: 0.55 };
    shader.uniforms.uPulseAmp = { value: 0.45 };

    shader.fragmentShader = shader.fragmentShader.replace(
      "void main() {",
      "uniform float uTime;\nuniform float uPulseSpeed;\nuniform float uPulseMin;\nuniform float uPulseAmp;\nvoid main() {",
    );

    shader.fragmentShader = shader.fragmentShader.replace(
      "#include <dithering_fragment>",
      "float pulse = uPulseMin + uPulseAmp * abs(sin(uTime * uPulseSpeed));\ngl_FragColor.rgb *= (0.65 + pulse * 1.3);\n#include <dithering_fragment>",
    );
  }}
/>
```

So the material is generated by Three.js, then you patch specific source snippets before compilation.

## 3. What Each Uniform Means

- `uTime`
  - Time value used for animation.
  - Updated every frame in `useFrame`.

- `uPulseSpeed`
  - Controls blinking speed/frequency.
  - Higher value means faster blinking.

- `uPulseMin`
  - Base floor brightness.
  - Prevents the sphere from going fully dark.

- `uPulseAmp`
  - Pulse amplitude (how strong the variation is).
  - Larger amplitude means stronger blink contrast.

## 4. How the Blink Is Calculated

This line creates the pulse curve:

```glsl
float pulse = uPulseMin + uPulseAmp * abs(sin(uTime * uPulseSpeed));
```

Then this scales final color:

```glsl
gl_FragColor.rgb *= (0.65 + pulse * 1.3);
```

Meaning:

- The sphere brightness goes up and down over time.
- It never goes negative.
- `abs(sin(...))` creates a repeated peak pattern.

## 5. How Time Gets Into the Shader

In your `useFrame` loop, you update `uTime`:

```tsx
if (spherePulseShaderRef.current) {
  spherePulseShaderRef.current.uniforms.uTime.value += 0.03;
}
```

This is what drives animation every render frame.

Tip: for framerate-independent timing, use elapsed time:

```tsx
useFrame((state) => {
  if (spherePulseShaderRef.current) {
    spherePulseShaderRef.current.uniforms.uTime.value = state.clock.elapsedTime;
  }
});
```

## 6. Why You Still Set `color` and `emissive`

Even with custom GLSL injection, base material values still matter.

- `color` controls base surface tone.
- `emissive` controls self-light contribution.
- Your custom GLSL multiplies final color, so these values are the starting palette.

## 7. Starter Tuning Recipes

- Slow breathing glow
  - `uPulseSpeed = 0.8`
  - `uPulseMin = 0.65`
  - `uPulseAmp = 0.25`

- Medium pulse
  - `uPulseSpeed = 2.0`
  - `uPulseMin = 0.5`
  - `uPulseAmp = 0.45`

- Fast alert blink
  - `uPulseSpeed = 6.0`
  - `uPulseMin = 0.2`
  - `uPulseAmp = 0.8`

## 8. Next Learning Steps

1. Replace `abs(sin(...))` with `step(...)` for hard on/off strobe.
2. Add a second color uniform and blend between two glow colors.
3. Add fresnel (view-angle glow) to make edges brighter.
4. Move shader code into a dedicated shader file once comfortable.

## 9. Quick Mental Model

- React sets uniforms.
- Three compiles shader.
- GPU runs fragment shader per pixel.
- `uTime` changes each frame.
- Pixel color changes = visible blink.

You are already doing real shader work. This setup is a strong foundation before moving to full custom `ShaderMaterial`.
